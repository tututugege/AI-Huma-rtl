# scripts/ 索引

| 类别 | 脚本 | 作用 |
| --- | --- | --- |
| 路径配置 | `env.sh`、`ttg_env.py` | 所有脚本共用的位置（`RTL_ROOT`、`AI_HUMA_ROOT`、`TTG_PROGS`、`TTG_BIG`、`TM`、`FM_GIT` / `FM_REV`：测试平台链接的 function-model 仓库和固定版本），全部由所在位置推出，可由环境变量覆盖 |
| 构建/检查 | `lint.sh`、`rtl_files.sh`、`gen_cfg.sh`、`gen_pmu_pkg.py`、`gen_tracker.py` | 规范检查（目录级，`rtl/` 下每个模块目录单独编译；`rtl/common/<族>`（如 `sram`）每个文件各作一次顶层）、RTL 文件序（配置包 → 其他 `*_pkg.sv` → 其余）、配置包（`make cfg`，rv64gc 默认）、PMU 事件包（`rtl/pmu/pmu_ev_pkg.sv`，来自 trace-model `pmu_events.def`）、进度表生成 |
| 整芯片检查 | `lint_chip.sh`、`lint_soc.sh` | `lint_chip.sh` 以 `soc_top` 为顶、`lint_soc.sh` 以 `chip_top` 为顶跑 Verilator `-Wall`（`lint.sh` 只按目录查），打印告警数，0 为通过 |
| 真实 SoC 回归门禁 | `soc_gate.sh` | 一键跑 `lint_soc.sh` + `tb/axi_unit`（`--assert`）+ `tb/soc/soc_tb`（`chip_top` 全套定向测试：smoke / UART FIFO 与外部 `rxd` / PLIC 外部中断优先级与 S-mode `seip` / `sw_rst_req` 软复位转 SRAM 启动 / `boot_mode=10` park / `DDR_DATA_W=128`）；`--linux` 可选加跑 `linux_j.bin` |
| 综合对比 | `synth_cfg.sh <标签> <配置包> <模块...>`、`synth_module.sh`、`synth_depth.sh` | 在指定配置包下逐模块综合（与 docs/09 同设置），结果在 `build/synth_<标签>/`，结束后恢复原配置包；`synth_depth.sh` 另给逻辑级数代理。需要 yosys + yosys-slang |
| **快速 PPA 评估（Tier 0~2b）** | `fast_ppa.sh`、`list_sv_files.py`、`run_tier1_yosys_pt.sh`、`buf_high_fanout.py`、`run_tier2_dc_fast.sh`、`run_tier2b_dc_inc.sh` | 四层快速面积/时序评估统一入口（`--tier 0\|0-elab\|1\|2a\|2b --host eda-XX`，禁止无 PDK 本机或 `login-inband` 直跑）：**Tier 0** 调总仓 `scripts/ppa_est.py` 毫秒级/秒级算 SRAM 宏颗数、面积、Padding 浪费与访问下界；**Tier 1** Yosys TSMC28 LVT + 真实 SRAM + 高扇出缓冲树修复 + PrimeTime 真实 STA（提速 `13.7×–48.6×`，面积排行 `Spearman=1.000`、Fmax `0.929`）；**Tier 2a** DC `dc-ultra-relax` 导 `.ddc` 并得含真宏 `<1%` 精准面积；**Tier 2b** 复用 `bpu.ddc` + `icache.ddc` 增量拼装 `front_top`（提速 `8.0×`）。实测口径见 [09-synthesis-report.md](../docs/09-synthesis-report.md) §22 |
| 整核闭环（周期） | `soc_smoke.sh`、`cmp_trace_model.sh`、`first_diff.sh/.py`、`tm_cycles.sh` | 整核 RTL（`tb/core/core_tb`）跑程序，周期/指令数与 trace-model 对比（**性能指标，不是门禁**）；`first_diff` 在同一程序上对出第一处周期/PC 分歧；`tm_cycles.sh <trace-model 二进制>` 在 `ref_cycles.txt` 的程序上跑模型的默认配置；改参考表用 `regen_refs.sh`（两张表一起写，带来源说明） |
| 程序表 | `progs.txt`、`progs_smoke.txt`、`ref_cycles.txt` | 程序列表；`ref_cycles.txt` 是 trace-model 在当前默认配置下的周期数（gate 基线 + dhrystone/coremark + `directed/`），RTL 应与之逐个相等；配置改变时由 `regen_refs.sh` 统一重生成 |
| 正确性门禁 | `fm_gate.sh <core_tb> <输出目录>`；测试平台用 `SOC_FM=1 CORE_OUT=<绝对路径> bash tb/core/build.sh` 构建 | `ref_cycles.txt` 里 77 个程序（rv64gc）逐条提交对比 function-model（见 `docs/modules/soc_top.md`），输出 `summary.txt`，并检查 SVA/断言报错与 `ref_cycles.txt` 周期差；`tb/core/build.sh` 支持可选验证开关（默认均关，不拖慢快速测试）：`SOC_ASSERT=1`（`--assert`）、`SOC_SVA=1`（挂 `rtl/sva/*.sv`）、`SOC_XINIT_UNIQUE=1`（`--x-initial unique`）、`SOC_COV=1`/`all`（行+SVA/含 toggle 覆盖率）；运行期 `SOC_TB_FM_STRICT=1` 额外校验 MMIO/跨字 store 数据及 18 个架构 CSR + 特权级；运行期 `SOC_TB_RAND_INIT=<种子>` 给所有寄存器和存储随机上电值（需 `SOC_XINIT_UNIQUE=1` 构建，可加 `CORE_VOPT=-DSYNTHESIS`），检查设计不依赖上电值 |
| 官方 ISA 合规 | `riscv_tests_gate.sh <core_tb> <输出目录>` | 编译并并行运行官方 RV64 `riscv-tests`（`rv64ui`/`um`/`ua`/`uf`/`ud`/`uc`/`uzba`/`uzbb`/`uzbc`/`uzbs`，153 项，默认跳过不支持的非对齐 `rv64ui-ma_data`，当前 152/152 PASS） |
| 随机 Fuzzer | `tools/fuzz/{gen_prog.py,fuzz_run.py,minimize.py}` | 微架构感知 RV64GC 随机程序生成器（5 种 Profile）+ 多核并行对拍（支持 `--tb` 对拍 RTL 与 `--spike-fm` 对拍 Spike）+ Delta Debugging 自动二分缩减器（见 `tools/fuzz/README.md`） |
| 单元等价检查 | `mul_check.sh`、`div_check.sh`、`fp_synth_check.sh` | 乘法器（Radix-4 Booth 结构版 vs 行为版）、除法器（Radix-16 Early-out vs 精确值）、自研可综合 RV64FD FPU（5 核心逐位对拍 SoftFloat）的独立测试 |
| Linux 整机 | `build_soc64_linux.sh [目录]`、`linux_gate.sh <core_tb> <模型> <镜像> [周期] [输出]` | **全程 Linux 回归**：`build_soc64_linux.sh` 构建 rv64 测试平台（逐条 function-model 检查、EBREAK_TRAP（`rob_pkg` 默认开）、**默认 4 个仿真线程**，`THREADS` 可改，需 `FMLIB`）；`linux_gate.sh` 同镜像同周期数跑 RTL 和 trace-model，三项全过才算通过：逐条检查无不一致、每区间 PMU 一级事件完全相同（`align_check.py`）、控制台到 `login:`。不带 `--threads` 的单线程构建跑全程要慢 2~3 倍，只用于几百万周期以内的检查点复现 |
| Linux | `linux_segments_cmp.sh <core_tb> <模型> <检查点目录> <输出目录> [每段周期]` | **Linux 检查点窗口并行，RTL 对 trace-model**：每个检查点两边都冷启动，跑同样的周期数，PASS = 逐条检查无不一致且 PT/UP 指纹相同（PMU 区间不比，`PMU_CMP=1` 打开）；`JOBS` 并行数、`SEGS` 选窗口、`TM_ENV` 给模型加环境变量。比 140M 周期的完整 gate 快得多，完整 gate 留作最终确认 |
| Linux | `linux_segments.sh <core_tb> <检查点目录> <输出目录> [每段周期]` | Linux 检查点段并行逐条对比（冷启动微结构，周期不比）；整机从复位启动见仓库根 `README.md`（`SOC_TB_SEMIHOST=1`，测试平台用 `build_soc64_linux.sh` 构建） |
| 构建准备 | `build_progs.sh`、`fm_lib.sh` | `build_progs.sh`：用 trace-model 的 `build_tests.sh` 把门禁程序（rv64ima）编到 `$TTG_PROGS/tests`（`TM_SRC` 选 trace-model 树）；`fm_lib.sh`：打印测试平台链接的 function-model 构建目录，没有就按 `FM_REV` 构建（XLEN=64 FP=1 RVC=1，放在 `build/fm-<rev>-x64c1`） |
| 分歧定位与波形 | `align_check.sh <prog.bin> [core_tb] [模型]`（调 `align_check.py`）、`drill_pmu.sh <core_tb> <模型> <VCD 版 core_tb> <镜像> <周期上限> <输出目录> [iv]`、`build_soc_vcd.sh [目录]`、`vcd_query.py` | `align_check`：单程序比每区间 PMU 一级事件和 BPU `PT`/`UP` 指纹，报第一个不同的区间（`DRILL=1` 自动下钻）；`drill_pmu.sh`：从复位找第一个 PMU 区间差异并抓该窗口波形（共两次 RTL 运行）；`build_soc_vcd.sh`：带波形导出的 `core_tb`（`SOC_TB_VCD=<起>:<止>:<文件>`，只用于调试）；`vcd_query.py`：按层次名正则查 VCD 信号，逐周期打印 |
| 文档 | `fill_depth.py` | 把 `build/synth_<标签>/<模块>.ltp`（`synth_depth.sh` 的结果）填进 `docs/modules/*.md` 的 `depth:` 行和第 6 节占位 |
| 其他 | `build_dcache_tests.sh`、`pmu_parity.sh` | 定向 DCache 覆盖程序的构建（`tests/dcache`，需 LLVM `clang` + `ld.lld`）；PMU 一级事件 RTL 对 trace-model 的逐事件总数对比 |

**rv64**：main 上只有 rv64gc；`fm_gate.sh`、`soc_smoke.sh` 直接用 `core_tb`（`SOC_FM=1 bash tb/core/build.sh`）；真实全片 SoC（`chip_top`）使用 `soc_tb`（`bash tb/soc/build.sh`）与 `scripts/soc_gate.sh`。rv32 在分支 `rv32-legacy`。

逐模块锁步、trace 录制/回放、变异检查和旧参考模型副本已退役：脚本在标签 `legacy-reference`（rtl 仓库）里。
