# <模块名> 设计文档

> 本模板的范例是 [isu.md](isu.md)。规则见总仓库 `docs/WORKFLOW.md` 第 7 节：**先改文档再改 RTL，提交前对照 diff 核对 RTL 与文档，文档和 RTL 在同一个提交里。** 数字写具名常量；继承的说法要重核，核不了的单列"未核对"；用大白话，占位和死代码要么删要么讲清楚。

## 1. 职责
这个模块每拍做哪几件事；对应哪个模型调度单元、它的阶段顺序。

## 2. 配置
`ttg_cfg_pkg` / 模块 pkg 里的参数：大小、位宽、个数、端口表，每项写出常量名。

## 3. 接口
按信号组列：方向、含义、位宽。多于几十个端口时分组。

## 4. 结构
框图；文件表（文件、行数、一句话职责，目录里每个文件都要有）；状态（寄存器、阵列、大小、读写口数）。

## 5. 一拍内的数据流
谁先算、谁依赖谁；同拍覆盖、寄存、优先级、flush 行为。大模块按流水级或阶段分小节。

## 6. 关键路径与深度
单模块综合深度（数字、日期、口径）；最长路径经过哪里（逐段）；这个模块里为降深度做过的改动（带提交号）。从代码读出而没综合验证的，明说。

## 7. 与模型的差异和取舍
有意没复刻的；容易误判为 bug 的细节；编译期开关与模型开关的对应。末尾单列"未核对"。

## 8. 验证
现有的门禁和模块级测试（路径）；没有模块级测试就明说，列"待补"。

## 9. 参数与开关速查
本模块相关的参数、开关、位表。

## 10. 变更记录
按日期或提交号，一行一项；更早的写"见 git 历史"。
