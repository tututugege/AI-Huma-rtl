## 深度导向版（`SYNTH_DEPTH=1`，balance + dc2）与关键路径

| | 轻量 ABC | 深度 ABC |
|---|---|---|
| 单元总数 | 3,241,863 | 4,075,991（+26%，平衡换来的面积） |
| 触发器 | 约 95,200 | 同量级（存储块 640 个不变） |
| 最长路径 | 309 级 | 303 级 |
| 耗时 / 峰值内存 | 1,659 s / 18 GB | 1,788 s / 20.7 GB |

两版最长路径级数几乎一样，说明这条路径是真实的，不是 ABC 没平衡造成的。

深度版关键路径（303 级），起点 `u_back.u_exu.u_ctrl.u_slot.g_slot[12].slot_q`，终点 `u_back.u_lsu…u_ldq.g_e[11].u_ent.f_q[66:35]`：

| 级数 | 段 | 说明 |
|---|---|---|
| 0–64 | EXU 控制 slot → `exe2lsu_ldu_req_uop_result` | 发射 / 地址生成 |
| 74–212 | `lsu2mmu_ldq_req_vaddr` → `u_dtlb.u_core` 的 `g_lane[0..6]`（`match`、`other_walk`、`refill_match`、`chain`）→ `mmu2lsu_stq_resp_result` | 约 140 级，近一半 |
| 214–238 | `tl_s` → `u_stq.g_e[7].u_ent.paddr8` → `sta_info` | STQ 地址比较 |
| 238–295 | `u_ldq.g_l2w[1]…u_wk.inf → conf → o → u_ent.ew` | LDQ 唤醒 / 冲突判断，约 60 级 |

原因：DTLB 的表查找（`table_hit` / `table_xlat`，CAM）各 lane 并行，没有问题；串联的是 `tlb_mmu_core` 里 `chain[0] → lane0 → … → lane6 → chain[7]`：每个 lane 拿前一个 lane 输出的整个 `walk` / `refill` 结构做宽比较（`other_walk`、`refill_match`）再更新，7 级串起来。
这是照 C++ 模型的逐 lane 顺序循环翻译的写法；语义上同一时刻只有一个 PTW，可以改成“第一个需要 walk 的 lane（优先编码）+ 并行比较”，预计只要几级。LDQ 那一段还没看。

**本轮不改**（下一轮专门做面积，关键路径作为起点；改 DTLB 链前要用 `ref_cycles` 的 64 个程序和 rv64 的 58 个 C 程序确认周期不变）。
