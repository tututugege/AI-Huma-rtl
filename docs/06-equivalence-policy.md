# 06 等价性原则：什么必须一致，什么可以简化

**目标是"有意义的行为逐拍一致"，不是"复刻 C++ 的每一个字节"。** 参考模型是软件，里面有大量残留值、越界读、写了又被覆盖的中间量、恒为 0 的字段。RTL 不要为这些付出结构上的代价；RTL 应当比 C++ 简单得多。

## 0. 总原则（最高优先级，先于以下各节）

**只要求边界上每个周期的可观察行为功能等价。** 参考模型"怎么算"——函数调用结构、一拍内某个函数被调用几次、comb/seq 是否熔合在一个函数里、中间变量和临时对象、阶段的先后顺序、容器与指针——**一律不复刻**。RTL 用最自然的硬件结构表达同一个"每拍的输入到输出、旧状态到新状态"的函数即可。

- 例：参考模型里 `icache_comb_calc` 在预译码冲刷拍被调用两次（第二次是 invalidate），RTL 只需写出"这一拍结束时环境看到的输出和下一拍的状态"，用带优先级的一次次态规则表达，不需要两步推进。
- 例：C++ 在一拍内顺序改写同一个 `nxt` 数组（LSU），RTL 不为每个阶段保留一份整体拷贝，直接合并成按条目的写使能和写数据。
- **被覆盖的瞬态不复刻**：只在中间调用/中间阶段可见、最终被覆盖或无人消费的值，不比较、不建状态。
- **验证强度不因此降低**：功能等价仍用逐拍比较证明——整程序实时锁步 + trace 回放 + 变异检查 + 覆盖补充。"不复刻结构"不等于"不验证"。
- 边界取"这个周期结束时环境实际看到的最终值"，环境指前端/访存子系统/testbench 以及其他已翻译模块的实际读取者。
- 允许保留的"怪行为"仍是 §5 里那一类：**可观察的、会影响后续行为或被消费的**行为（如 BTB 未命中目标是 `bank_pc+4`、更新队列有损丢弃），必须复刻并登记疑点。

## 1. 必须逐拍逐位一致（spec 里严格比较）

凡是**有下游消费者在该状态下会读取并据此改变行为**的输出，都必须一致。典型：
- 带 `valid/enable/mispred` 限定且限定为真时的负载；
- 最终影响提交、周期数、访存、分支恢复的一切量；
- 状态机、指针、计数器、标志（它们决定后续行为）。

## 2. 可以不比较（用 `when`）——无效时的残留值

输出的限定条件为假时，C++ 里常常留着上一拍的值或未清零的值。**如果参考模型里没有任何消费者在限定为假时读它**，这个值就是无意义的：
- spec 里写 `when <限定信号>`，RTL 在无效时**输出什么都行**（建议清 0 或直接穿过，取最省的实现）。
- **必须先核对消费者**：在参考模型里搜这个信号的所有读取点，确认都被限定条件保护。把核对结果写进设计笔记（"信号 X：读取点 A、B 均受 valid 保护"）。核对不到就老实用严格比较，不得凭感觉放宽。
- 例：`ren2dis_*` 在 `ren2dis_valid[i]=0` 时的 uop 字段；`dec_bcast_redirect_rob_idx` 在 `mispred=0` 时；`dec_bcast_br_mask/br_id` 在 `mispred=0` 时（若 C++ 本来就清零则可严格比较，更简单）。

## 3. 可以直接删除——接口精简

- **spec 只包含有消费者的字段**：每个输出字段必须能指出参考模型里谁读它（或 testbench/difftest/提交路径读它）。恒为 0 的字段（如 `expect_mask`、`cplt_mask`）、只有 perf/debug 用的字段（`dbg.*`、tma 统计量）、被整个后级完全忽略的字段，**从 spec 和 RTL 端口里删掉**。
- 输入同理：模块实际没用到的输入字段不要接。
- 删字段会改变 trace 布局，需要重新录制（用较小的拍数，见 AGENT_BRIEF）。

## 4. 不复刻：C++ 的未定义/不可达/调试行为

- 越界读（如 areg>32 读 RAT）、未初始化存储（`init()` 没初始化的数组）、sanity 检查、`assert`：RTL 不复刻，行为取最简（读 0 / 不关心），在设计笔记里写一句"不可达，trace 未出现"。
- 配置宽度/深度非 2 的幂时才需要的回绕逻辑：RTL 用位宽自然回绕，并加参数断言（`ttg_cfg_pkg` 里的值不是 2 的幂就在仿真里报错）。

## 5. 不得简化的情况

- **残留值会被消费的**：如果核对发现某个残留值确实被下游读取并影响行为，那是一个真实的状态，必须建成寄存器（04 第 3.1 节），并登记。
- **有疑点的**：怀疑是参考模型 bug 的行为，按参考模型实现，登记到 `deviations.md` 的"疑点"栏，由协调者决定。**不要因为"C++ 怪"就改变有意义输出的行为。**

## 6. 简化仍需证明

- 每次放宽（加 `when`）或删字段后，**全部 trace 仍须通过**，并且**变异检查仍须有效**：至少 3 个变异必须被严格比较的字段抓到。若放宽之后某类变异再也抓不到，说明放宽过头。
- 设计笔记第 4 节列出：放宽了哪些字段（及消费者核对结果）、删除了哪些字段（及理由）、哪些 C++ 行为选择不复刻。

## 7. 结构上的要求（简化的目的）

- 不为残留值建寄存器；不为"无效槽保留旧负载"设计特殊的 kill/hold 优先级；一个槽有效时才有负载，无效时不关心。
- 内部不要照搬 C++ 的中间变量；按硬件功能组织数据流。
- 若 C++ 的一拍内多次覆盖同一量，只保留最终有意义的结果，用清晰的优先级表达。

## 8. debug / perf / TMA 字段与 PMU（不设计进 RTL）

**判断标准是"谁读它"，不是字段名。**

1. **只服务可观测性的字段不进 RTL、不进 spec**：`dbg.*`、用于打印的 pc、perf 计数器、`tma.*`（top-down 归因标志，只喂 C++ 的 PerfCount）。它们在参考模型里沿流水线一路搬运，只是为了最后喂统计；硬件里不需要这条边带，也未必能便宜地实现。
2. **名字会误导，必须看消费者**：
   - `diag_val` 虽叫"诊断值"，实际是分支的实际目标地址，被 BPU 训练和 flush 重定向读取，**是功能字段，必须保留**。
   - `tma.mem_commit_is_store/is_load` 的唯一功能读取点是 `SimCpu::commit_sync`：它决定"提交时是否对**模拟器的存储模型**写入"，是模拟器自己的记账。硬件里这件事由 LSU 的 store 队列提交逻辑完成（`comb_stq_commit`），所以这对字段**不进 RTL**。验证环境（testbench）如果需要，从已经比较的 `uop.type`/`is_atomic` 等推导。
3. **边界的选择**：后端边界只包含硬件上有意义的输出；仅为模拟器记账而存在的输出（如 tma 边带）不进边界 spec，也不要求 RTL 产生。
4. **PMU 单独设计，不是 PerfCount.h 的翻译**：参考模型的性能计数（`PerfCount.h`，约 1400 行，含 TMA 归因）里很多统计在硬件上不容易实现（需要跨流水线携带归因信息、浮点 IPC 窗口统计等）。RTL 的 PMU 将作为独立模块重新设计：用硬件友好的事件（周期数、提交指令数、分支误预测、cache miss 等）挂在已有信号上，不要求与 C++ 计数器逐拍一致，不属于逐拍对照的范围；与参考计数器的对照只在事件定义一致时做汇总层面的比较。
5. **清理遗留（已完成 2026-11-04）**：`tma_mem_commit_is_load/store` 目前仍从 Idu 带到 Ren、Rob（及 back_top 的一处胶水）。在整核接线稳定后做一次清理：从 Idu/Ren/Dispatch/Rob 的 spec 与 RTL 中删除，各模块重新回放/锁步确认仍然全绿。
